# Discipline Workflows

Read this reference when agents may resist, shortcut, or rationalize away a workflow rule.

## Start from the target behavior

State what the agent should do and the observable condition that permits it to proceed. Use direct authority proportional to the cost of violation.

Add explicit prohibitions only for:

- shortcuts observed in baseline evaluations;
- irreversible, unsafe, or otherwise high-cost failure paths;
- ambiguity that cannot be removed with a positive instruction alone.

Pair every prohibition with the required alternative:

> Preserve the working tree unchanged until the plan is approved. If approval is absent, present the plan and wait.

This is more actionable than either “do not edit yet” or a generic “follow the process.”

## Pressure-test resistance

Build realistic scenarios that make violation attractive. Combine at least three pressures when the rule is costly to follow:

- time or urgency;
- sunk work;
- authority requests;
- economic consequence;
- exhaustion;
- social pressure to appear flexible.

Require a concrete choice or action. Run the scenario without the proposed instruction, record the choice and rationalization verbatim, then rerun it after the minimum change.

## Close observed loopholes

For each rationalization:

1. Identify the ambiguous or missing instruction it exploited.
2. Strengthen the positive action or completion criterion.
3. Add a narrow prohibition only if the positive instruction still permits the shortcut.
4. Add the scenario to the regression set.
5. Rerun it from a clean context.

Do not accumulate generic warnings. A long list of imagined violations gives them undue prominence and creates maintenance burden.

## Resolve letter-versus-spirit failures

When an agent claims an alternative follows the “spirit” of a rule, make the rule's observable invariant explicit. For example:

> Implementation begins only after a test has failed for the expected missing behavior. Code written before that evidence does not satisfy this workflow.

The invariant explains both the required action and why superficially similar alternatives fail.

## Self-checks

Use a rationalization table or red-flag list only when evaluations show that agents recognize the phrase and correct course. Keep each entry tied to a regression scenario.

A discipline workflow is ready when the agent:

- follows the target behavior under realistic combined pressure;
- cites the operative rule or completion criterion;
- does not invent an untested hybrid workaround;
- repeats that behavior across the intended models;
- passes every observed-rationalization regression.
